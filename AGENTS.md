# Architecture rules
- Revenue filters, breakdowns and chart labels derive their fiscal periods from the shared fiscal quarter utility so calendar boundaries and exported labels stay consistent.
- Planning Editor, Project Assignment Matrix and Project Hours Matrix use the shared planning horizon utility so their last selectable year stays aligned.
- Project allocation details derive weekly month headers from ISO Thursday dates and limit contextual leave to the project's actual allocation period, preventing unrelated future leave from extending project columns.
- Keep project-hours aggregation in a pure utility, separate from its view, so split allocations and period totals can be tested independently.
- Keep status-based project-hours summary breakdowns in a pure utility using the live project catalog; generic demand contributes hours but never fabricates named engineer headcount.
- Keep project matrix capacity summaries in a pure utility; raw productive totals match project cells while utilization caps each person's contribution independently to available capacity.
- Read planning through PlanningContext; synthetic secondary rows must not double-count primary-row secondary fields.
- Project-hours filtering reads the live Project Management catalog; Program mode masks out-of-program allocations before both aggregations, while Custom mode selects engineers through the shared saved-view hook, keeping project cells and productive totals consistent.
- Project-hours and capacity summaries share working-date allocation using the existing engineer company list to choose holiday calendars; monthly raw hours remain conserved across working dates and FTE denominators are person-specific.
- Persist the project-hours filter and saved-view identity in validated browser storage, restoring lazily without overwriting an edited selection when saved views load.
- Export Project Hours Matrix through a lazy-loaded ExcelJS helper using numeric table snapshots and computed UI colors, embedding the currently rendered capacity chart on the same worksheet to preserve filters, styling and chart mode.
- Keep Project Assignment Matrix lookups indexed in Maps, compute its weekly/monthly summary rows in one pass through `matrixSummary`, and render cell tooltips through one shared imperative overlay so large horizons do not mount per-cell tooltip trees or scan planning entries per cell.
- Load `planning_matrix` in parallel page batches selecting only needed columns (omitting SQL `normalize_name`) with a stable loader and debounced realtime subscription so initial loads and bulk edits do not trigger redundant full-table refetches.
- Derive the 1 FTE capacity calendar and date-range MH calculator in a pure utility (`fteCapacityCalendar`) from `workingDays.ts` Czech holidays so annual tables, quarterly averages, chart totals and multi-person range calculations stay consistent and testable.
